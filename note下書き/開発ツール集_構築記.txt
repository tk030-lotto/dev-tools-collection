タイトル: 完全クライアントサイドで動く「開発ツール集 (DevTools Suite)」を React + TypeScript で作った話 〜Zero-Dependency とプラグイン設計の裏側〜

---

■ はじめに

個人開発やAI協調開発を進める中で、「ちょっとしたドキュメントのリンク切れを調べたい」「GitHubにPushする前にAPIキーやTODOコメントが残っていないか点検したい」「プロンプトのバージョン間差分をサクッと確認したい」といった場面によく遭遇します。

しかし、既存のWebツールに機密情報や開発中のコードをアップロードするのはセキュリティ面で抵抗があります。

そこで今回、すべてのデータ処理をブラウザ内部で完結させ、サーバーへデータを一切送信しない完全ローカル完結型Webアプリケーション「開発ツール集 (DevTools Suite)」を React + TypeScript + Vite で構築しました。

本記事では、この開発ツール集のアーキテクチャ設計、Zero-Dependency での実装工夫、開発中に直面した泥臭い技術的ハマりポイントとその解決策について詳しく紹介します。


■ 1. アーキテクチャ設計：PluginRegistry と ErrorBoundary によるモジュール拡張性

本アプリケーションでは、後から新しい開発ツールを簡単に追加・拡張できるように「コア基盤」と「機能プラグイン」を明確に分離したプラグインアーキテクチャを採用しました。

1. ToolPlugin インターフェース
各機能ツールは以下のような TypeScript インターフェースに従って実装されます。

```typescript
export interface ToolPlugin {
  id: string;
  name: string;
  description: string;
  icon: string;
  category: PluginCategory;
  version: string;
  component: React.ComponentType<PluginComponentProps>;
}
```

2. PluginRegistry API
シングルトンの Registry クラスを介して、ツールを動的に登録（register）・検索・切り替え管理します。

3. PluginErrorBoundary によるエラー絶縁
特定のプラグイン内で予期せぬ例外が発生しても、アプリ全体がクラッシュ（画面真っ白）するのを防ぐため、各プラグイン描画部を `PluginErrorBoundary` で安全にラップしています。これにより、万が一エラーが起きても該当ツールの枠内だけにエラーメッセージが留まり、他ツールへの影響を遮断しています。


■ 2. 開発でこだわった3つのポイント

① Zero-Dependency First：自作 LCS 差分演算エンジン
「PromptDiff（プロンプト差分比較ツール）」を実装するにあたり、外部の diff ライブラリを追加せず、標準のアルゴリズムである LCS (Longest Common Subsequence: 最長共通部分系列) を用いた差分計算エンジンを自律実装しました。
行単位の差分比較に加え、行内のどの単語が追加・削除されたかを特定する単語レベル (Word Diff) のトークナイズ処理も自作し、バンドルサイズの軽量化と外部依存ゼロを両立させています。

② 徹底したプライバシー保護：完全クライアントサイド完結 (Zero-Server)
ファイル読み込みには HTML5 の `FileReader API` を使用し、分析結果のエクスポートには `Blob` や `URL.createObjectURL` を利用しています。
外部サーバーへの HTTP リクエストやバックエンド処理は一切存在しないため、APIキーや社内ドキュメントをドラッグ＆ドロップしても外部漏洩のリスクがありません。

③ 妥協しない UI/UX：グラスモルフィズム & レスポンシブ
単なる機能確認用 MVP に留めず、ダークモード/ライトモード切替機能、グラスモルフィズム（すりガラス効果）、CSS マイクロアニメーションを適用しました。
また、画面幅 375px のスマートフォンから 4K ディスプレイまで対応するフルレスポンシブデザインを Vanilla CSS で組んでいます。


■ 3. 開発中にハマった技術的ポイントと解決策

開発・テストの過程で直面した2つの技術的トラップと、その解決策です。

トラップ1: 改行コード (CRLF vs LF) の違いによる「全行誤差分」現象
Windows 環境で作成したファイルと Linux/Mac 環境で作成したファイルを PromptDiff で比較した際、文字自体は全く同じなのに「全行が削除＆追加（全変更）」と判定される問題が発生しました。
原因は Windows の改行コード `\r\n` と Unix の `\n` の違いでした。
解決策として、LCS 比較ロジックにテキストを投入する直前で、一律 `replace(/\r\n/g, '\n').replace(/\r/g, '\n')` により改行コードを正規化する処理を追加し、誤差分を完全にシャットアウトしました。

トラップ2: GitHub Pages に公開すると画面が真っ白になる「Vite base パス問題」
Vite で構築したアプリを GitHub Pages（例: `https://<user>.github.io/dev-tools-collection/`）のサブディレクトリ配下で公開すると、デフォルト設定では JS や CSS がルート `/assets/...` を参照してしまい、404 エラーで画面が白くなってしまいました。
解決策として、`vite.config.ts` の設定に `base: './'`（相対パス）を指定しました。これにより、ビルドされる `index.html` 内の成果物参照パスが `./assets/...` となり、どのサブディレクトリ配下でも正しく表示されるようになりました。


■ 4. 搭載ツール一覧

現在、以下の5つのツールを搭載・稼働させています。

1. MarkdownLinkChecker: Markdown 内の相対パス・画像参照切れ・アンカーリンクの自動検証
2. GitHubPreflight: 公開前の APIキー検出、TODO残存コメント、不要ファイル点検
3. HandoffPack: 要件・TODO・READMEを統合した AI 引き継ぎプロンプト生成
4. PromptDiff: プロンプト/テキストの行・単語単位カラーハイライト差分比較
5. DocumentConsistencyChecker: 複数ドキュメント間の用語表記ゆれ・タスクID矛盾の一括検証


■ おわりに

個人開発や社内業務において、「安全かつ即座に使いたい」というニーズに応える開発ツール集が出来上がりました。

モジュール化されたプラグイン構造に設計してあるため、今後も「こんなツールが欲しい」と思った際に数時間で新しいプラグインを追加・拡張していく予定です。

本記事の知見や設計パターンが、フロントエンド開発やクライアントサイドツール構築の参考になれば幸いです！
